# Encryption-at-rest audit — PNG6 local stack (antix)

Date: 2026-10-01. Scope: the Docker Compose stack on SB's laptop, local-only.
"Encrypted" below means: bytes on disk are ciphertext without the key.
Honest "not encrypted" findings are recorded as such.

## Summary

| Store | At rest | In transit | Residual risk |
|---|---|---|---|
| Postgres 16 (`pgdata` volume) | NOT encrypted | TLS on both ends (verified) | Host disk access reads all data |
| MinIO (`miniadata` volume) | SSE-S3 available, opt-in per object (verified working) | HTTP inside compose net (not TLS) | App uploads land unencrypted unless requested |
| Redis (RDB/AOF) | NOT encrypted | Plaintext inside compose net | Cache contents readable from host disk |
| RabbitMQ (`rabbitdata`) | NOT encrypted (durable queues) | Plaintext inside compose net | Job payloads readable from host disk |

## Details

### Postgres
- Server TLS enabled (`ssl=on`, self-signed cert from `deploy/pg-tls`, generated per
  host by `deploy/gen-local-tls.sh`). Plaintext still accepted (server does not force).
- App tier (api/worker/beat) sets `PGSSLMODE=require`; `_pg_ssl_context()` in
  `backend/src/planner/core/db.py` builds an `ssl.SSLContext` (CERT_NONE, no hostname
  check — correct for the self-signed local cert). Verified live: app connection
  reports `ssl=True, TLSv1.3, TLS_AES_256_GCM_SHA384`.
- Alembic at container start and ad-hoc `psql` still connect plaintext (server allows).
- At rest: the `pgdata` Docker volume is plaintext. No TDE, no volume encryption.
- Public-deploy path: host-level volume encryption (LUKS), real CA + verify-full,
  and `hostssl` enforcement in pg_hba.

### MinIO
- Built-in single-key KMS enabled via `MINIO_KMS_SECRET_KEY` (in repo-root `.env`,
  gitignored; key name `png6-local`). Wired through the hardening overlay via
  `env_file: ../.env` (compose interpolation reads `deploy/.env`, which does not
  exist — hence env_file, not `${VAR}`).
- Verified live: object PUT with SSE-S3 → `HeadObject` returns
  `ServerSideEncryption: AES256`. Objects written without the header stay plaintext.
- The app does not currently request SSE-S3 on uploads, so dataset files land
  unencrypted. Enabling bucket-default encryption or app-requested SSE-S3 is the
  follow-up.

### Redis
- Persistence (RDB snapshots / AOF) is plaintext on its Docker volume.
- Holds cache data (profiles, query results, model responses). No auth/TLS inside
  the compose network (binds to the compose net only; not published to host).
- Follow-up for sensitive use: host-level volume encryption; Redis 7 ACL + TLS if
  the threat model needs it.

### RabbitMQ
- Durable queues persist messages plaintext to `rabbitdata`.
- Management UI (15672) and AMQP (5672) are published to the host but reachable only
  via the tailnet/localhost on this laptop; no public exposure.
- Healthcheck timeout relaxed to 20s in the overlay (diagnostics ping flakes on
  this host; broker serves AMQP fine).

## Key material hygiene
- `deploy/pg-tls/server.key` and `.env` are gitignored; the Caddy local CA lives in
  the `caddy_data` Docker volume. All are throwaway, per-host, regenerated by
  `deploy/gen-local-tls.sh`. Never commit them.
- Public deployment needs: real secrets management (not `.env`), ACME certs for
  Caddy (see Caddyfile comments), and host-level disk encryption.
